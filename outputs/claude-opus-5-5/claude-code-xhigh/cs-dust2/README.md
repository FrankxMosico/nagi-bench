# DUST2 // 5v5 浏览器 FPS 原型

React 18 + TypeScript + three.js 实现的第一人称爆破模式原型：Dust2 核心区域、5v5（你 + 4 AI 队友 vs 5 AI 敌人）、手枪局开局、C4 下包/拆包、Hitbox 伤害、AWP 开镜、小地图、程序化音效。

**不使用任何外部资产**：地图、角色、武器全部由代码生成几何体；贴图在运行时画到 `<canvas>` 上；声音全部用 Web Audio 合成。运行时依赖只有 `three`、`react`、`react-dom`。物理、寻路、AI 状态机、渲染循环均为自研。

## 运行

```bash
npm install
npm run dev        # 打开 http://localhost:5173
```

需要支持 WebGL2 的桌面浏览器（Chrome / Edge / Firefox）。点击「开始游戏」后画面会锁定鼠标指针；按 Esc 暂停。

其他脚本：

| 命令 | 作用 |
| --- | --- |
| `npm run build` / `npm run preview` | 生产构建 / 预览 |
| `npm run typecheck` | `tsc --noEmit` 类型检查 |
| `npm test` | 语法检查 + 无头 5v5 模拟测试 + 浏览器端冒烟测试（需 Node ≥ 22.6） |
| `npm run test:rounds -- 1,2,3 hard 8` | 打印逐回合的 bot 对局日志与击杀地点统计（种子、难度、回合数） |
| `node --experimental-strip-types tests/duel.ts 80 normal` | 1v1 架点 vs 进攻对枪统计（AI 调参用） |
| `node --experimental-strip-types tests/mapshot.ts` | 把生成的碰撞地图、导航网格和示例路径俯视渲染到 `tests/out/map.png` |

## 功能对照

### 1. Dust2 地图（`src/engine/map/dust2.ts`）
- 以「房间 + 坡道 + 道具」描述地图（米制，+X 东、+Z 南，与经典雷达同向）。包含 **T 出生点、CT 出生点、A 大（A大外 → A大门 → A大拐角/坑位 → A大 → A坡）、A 点（含 Goose）、中路 / T 中路 / Xbox、中门、CT 中路、猫道（含楼梯）、A 小、B 洞（洞外 / 洞口 / 上洞 / 下洞）、B 门、B 点**。
- 走位与原图一致：T→A大→A点、T→中路→猫道→A小→A点、T→B洞→B点、T→中路→下洞→B洞、T→中路→中门→CT中路→B门→B点、CT→A点 / B门 / 中门。`npm run test:sim` 会对全部区域两两跑 A* 验证连通。
- **中门**：门框 + 两扇打开的门板（实体碰撞），留出 3.6 m 可通过的缝隙。A 大门、B 门同理。
- 墙体自动生成：所有不在房间/坡道内、且距可走区域 2 m 以内的格子都变成墙（贪心合并成盒子，高度有起伏）。地板是实心平台，所以猫道、A 点平台的边缘是真实的落差/墙面。B 洞带顶棚。
- 碰撞（`src/engine/physics.ts`）：盒体 + 线性坡道；角色按轴向分离滑动、可上 0.45 m 台阶、沿坡道贴地、顶棚阻挡。玩家与 AI 用同一套碰撞，无法穿墙；无头测试会每帧检查所有角色是否嵌入几何体。

### 2. 角色（`src/render/characterModel.ts`）
- 独立的头、躯干（+战术背心）、骨盆、双臂（上臂/前臂/手，两骨骼 IK 解算到枪的握把与护木）、双腿（大腿/小腿/靴，程序化步行循环、蹲姿、跳跃、阵亡后仰倒）。
- **T**：卡其色夹克、棕色皮背心、黑色头套 + 红色袖标/头带；**CT**：深蓝制服、蓝灰防弹背心、头盔 + 护目镜 + 浅蓝反光条。持包者背上挂着 C4。
- 默认持枪姿态，武器挂在随视角俯仰的躯干上，随角色朝向转动。队友头顶显示名字。
- Hitbox（`src/engine/hitbox.ts`）与模型尺寸一致，随朝向旋转、随蹲下插值。

### 3. 武器系统（`src/engine/weapons.ts` 数据驱动；`src/engine/game.ts` 逻辑）
新增武器只需加一条 `WeaponDef`（可选再加模型与音色）。

| 武器 | 槽位 | 伤害 | 射速 | 弹匣 | 特点 |
| --- | --- | --- | --- | --- | --- |
| AK-47 | 主 | 40 | 600 rpm | 30 | 上跳强（1.15°/发并递增，最高 12°）、扩散增长快 |
| M4A4 | 主 | 33 | 667 rpm | 30 | 后坐力约为 AK 一半，扩散增长小 |
| AWP | 主 | 125 | 41 rpm | 10 | 右键两级开镜（FOV 74°→40°→15° + 2D 瞄准镜遮罩），未开镜/移动时极不准；开枪后拉栓自动退镜再恢复；胸腹一枪致命 |
| Glock-18 | 副（T 默认） | 22 | 400 rpm | 20 | 穿甲差 |
| USP-S | 副（CT 默认） | 28 | 353 rpm | 12 | 消音 |
| Desert Eagle | 副 | 31 | 267 rpm | 7 | 伤害介于手枪与步枪之间、弹匣最小、首发准、连射乱飘、穿甲高 |
| 刀 | 近战 | 40 / 65 | — | — | 左键轻击、右键重击，背刺 ×2.25/×2.77 |

- 准星扩散 = 姿态基础值 + 移动（按速度）+ 空中 + 连发累积；准星间距按真实扩散角换算成像素。
- 视角后坐（punch）真实上抬镜头，子弹沿「视角 + 后坐 + 随机扩散」射出，停火后回落。
- **Hitbox 分区伤害倍率**：头 2.0、胸 1.0、腹 0.85、手臂 0.7、腿 0.55——爆头恰好是身体（胸部）的两倍。
- **护甲**：CS 式护甲比率——受保护部位（躯干/手臂，头部需头盔，腿部不受保护）只有 `armorPen` 比例的伤害进入血量，护甲按剩余伤害的一半扣除，护甲不足时溢出。
- 距离衰减、被击中减速（tagging）、换弹（可打断）、切枪拔枪时间、空仓自动换弹、拾取/丢弃武器。
- 第一人称：独立场景 + 独立相机渲染（不会穿墙），队伍颜色的袖子 + 手套，含行走晃动、鼠标惯性摆动、开火后坐、拔枪、换弹（弹匣拔出/插入）、刀挥砍/突刺、C4 输入动画、枪口火光。

### 4. 手枪局
第 1 回合默认是手枪局（菜单可改为长枪局开局）：全员只有默认手枪（T Glock / CT USP）+ 刀，无主武器；护甲按 `ROUND_PRESETS.pistol` 配置（凯夫拉 100、无头盔、无拆弹器），购买菜单只开放手枪。之后为长枪局（AK / M4、每队一把 AWP 与一把沙鹰、头盔、CT 有拆弹器）。原型没有经济系统，购买免费。

### 5. C4 与回合
- 回合开始随机交给一名 T（包括玩家）。持包者阵亡 → C4 掉落，任意 T 走过即可捡起；按 G 可主动丢包。
- 在 A/B 包点范围内切出 C4 按住左键 3.2 秒安放（需站定），40 秒倒计时，蜂鸣逐渐加快。
- CT 站在 C4 旁按住 E 拆除：10 秒，有拆弹器 5 秒；移动或松键会中断。
- 结算：CT 全灭或 C4 爆炸 → T 胜；T 全灭且未下包、拆包成功、或时间耗尽未下包 → CT 胜。先赢 8 回合者获胜。
- 阵亡后先有短暂的死亡镜头，然后以第一人称观战存活队友，按 E 接管该 bot 继续本回合。

### 6. 5v5 AI（`src/engine/ai/`）
- **寻路**：从碰撞世界采样出 0.5 m 的 2.5D 导航网格（高度、可站立性、从出生点的可达性、离墙距离），8 邻域 A*（离墙越近代价越高）+ 拉绳平滑；每帧有寻路配额，卡住会重算路径、侧移脱困，最后兜底吸附到可走格子。
- **感知**：10 Hz 视野检测——视野角（按难度）+ 距离 + 对头部/躯干的射线视线检测，被墙挡住就看不见；能听到枪声和脚步；被打会转向攻击方。目击信息共享给队伍（也用于雷达上的「已发现敌人」）。
- **个体状态机**（`bot.ts`）：idle / moving / holding / engaging / planting / defusing。交战时有反应时间、逐渐收敛的瞄准误差、按距离点射/扫射、按难度压枪、步枪站定射击、手枪横移、AWP 先开镜，主武器打空且距离近时切手枪。
- **队伍规划**（`planner.ts`）：T 每回合选择 A 或 B，按 A大/A小（猫道）或 B洞/中转B 分路，持包者走主路线并下包，其他人到包点架枪；C4 掉落时最近的 T 去捡；下包后全队守包。CT 默认 A×2（AWP 架 A 大）、中×1、B×2，发现多名 T 进攻某包点时轮转支援，下包后回防，最近的人负责拆包。
- 三档难度：简单 / 普通 / 困难（反应时间、转向速度、瞄准误差、爆头率、压枪、视野角）。

### 7. 操作与 HUD（`src/ui/`）
动态十字准星、命中/击杀/爆头提示、血量与护甲（含头盔/拆弹器/C4 标记）、弹药面板（当前弹匣 / 备弹 + 子弹条，换弹提示）、武器槽列表、右上角击杀播报（与你相关的高亮）、顶部比分/计时/存活人数/已下包倒计时、回合公告、下包/拆包进度条、操作提示、受击方向指示与低血量暗角、AWP 瞄准镜遮罩、记分板、购买菜单、主菜单/暂停/比赛结束界面。

**小地图**：常驻左上角，北朝上的 Dust2 俯视图（按高度着色、包点、出生点、箱子、门），实时显示自己（箭头朝向）、队友（编号 + 朝向，阵亡显示 ×）、被己方任何人看见的敌人（红点）以及 C4（已安放时闪烁；掉落/携带状态对 T 可见，对 CT 只有发现持包者时可见）。下方显示当前位置名称。

### 8. 声音（`src/audio/AudioEngine.ts`）
全部由噪声 + 振荡器 + 滤波器 + 程序生成的混响脉冲合成：AK（低沉厚重）、M4（更紧更亮）、AWP（巨响长尾 + 拉栓）、Glock、USP（消音「噗」）、沙鹰各自不同的枪声；换弹（卸弹匣/上弹匣/拉栓）、脚步、落地、AWP 开镜、命中提示（打头盔有金属「叮」）、击杀提示音、受伤、刀挥砍、C4 安放按键音/安放完成/倒计时蜂鸣/拆除/爆炸、回合开始与胜负音效。其他角色的声音经 HRTF 3D 定位，可以听声辨位。

## 架构

```
src/
├─ engine/            纯 TypeScript 模拟层（不依赖 three/DOM，可无头运行）
│  ├─ map/            Dust2 数据、墙体生成、callout 查询
│  ├─ physics.ts      碰撞世界：盒体+坡道、移动/台阶/重力、射线
│  ├─ nav.ts          导航网格 + A* + 路径平滑
│  ├─ weapons.ts      武器数据、回合预设、护甲伤害公式
│  ├─ hitbox.ts       分区 Hitbox 射线检测
│  ├─ soldier.ts      角色状态 + ControlInput（玩家与 bot 共用的输入接口）
│  ├─ game.ts         Game：回合状态机、移动、开火、伤害、C4、拾取、感知、观战/接管
│  ├─ events.ts       类型化事件总线（渲染/音频/HUD 订阅）
│  └─ ai/             bot.ts（个体状态机） planner.ts（队伍战术）
├─ render/            three.js 表现层：地图网格、贴图、角色、武器、第一人称、特效
├─ audio/             Web Audio 程序化音效
├─ client/            GameClient（主循环与各层的胶水）、Input、HudStore
└─ ui/                React HUD 与菜单
```

**三者的数据同步：**
- **物理/模拟帧**：`requestAnimationFrame` 驱动，模拟以固定 60 Hz 步长推进（累加器，单帧最多补 6 步）。按键按下沿会被锁存，直到下一个模拟步消费，短按不会丢。
- **渲染帧**：每个 rAF 渲染一次，角色位置/朝向在上一步与当前步之间插值；本地视角直接使用最新鼠标角度（不受模拟步长影响），再叠加模拟层的后坐力。一次性特效（枪口火光、弹道、弹孔、血雾、爆炸）与音效通过事件总线触发。
- **React**：`HudStore` 约每 15 Hz 生成一次不可变快照，内容变化时才通知，组件用 `useSyncExternalStore` 订阅；高频组件（准星、命中提示、小地图、开镜遮罩、受击方向）通过 `client.onFrame` 每帧命令式更新 DOM/canvas，不触发 React 重渲染。UI → 引擎通过 `GameClient` 的方法（开始、继续、购买、设置）。`GameClient` 在 `useEffect` 中创建、在清理函数中完整释放（rAF、监听器、WebGL 上下文、AudioContext），兼容 StrictMode 的双重挂载。

## 测试与验证情况

开发环境的网络策略拦截了 npm 源，所以 **没能在这里执行 `npm install`，也没有在真实浏览器里运行过，`tsc` 类型检查也没跑过**。已做的验证：

1. `npm run test:syntax`：用 Node 内置的 swc 解析全部 `.ts/.tsx`，确认语法正确、只用了可擦除的 TS 语法。
2. `npm run test:sim`（无头，真实引擎代码）：地图所有区域两两 A* 连通、各进攻路线/架点/下包点可达；碰撞（墙体、中门门框/门缝、猫道楼梯、A 点平台落差）；视线遮挡；伤害规则（爆头 = 2 倍、护甲、AWP 一枪、沙鹰数值区间、M4/AK 对比）；多局全 bot 5v5 对战——无 NaN、无人嵌墙、无 bot 卡住超过 3.5 秒、确实发生交火/下包/拆包。
3. `npm run test:rounds` / `tests/duel.ts`：用逐回合日志、击杀地点统计和 1v1 对枪统计调过 AI 与地图（例如发现并修掉了 CT 出生点与 T 出生点之间穿过中门的直线视野、猫道俯视 CT 中路的问题）。目前 bot 对局中三个难度的 T 方胜率都在约 44–56%；架点预瞄的一方在 1v1 中胜率约 55–70%，先开枪约 0.2 秒；下包、拆包、爆炸、全灭、超时等结局都会出现（具体比例随种子波动）。
4. `npm run test:smoke`：把 three.js / DOM / Web Audio / React 换成测试桩（宽松代理对象 + 迷你 JSX 转换 + 单遍迷你 React），在 Node 里真实运行 `GameClient`、渲染器、音频引擎和全部 HUD 组件，脚本化跑完：菜单 → 开局 → 购买沙鹰 → 移动/开火/换弹/切刀 → 记分板 → 暂停/继续 → 阵亡观战 → 接管 bot → 下包 + 拆包 → 购买 AWP 开镜/退镜 → T 方下包 → 爆炸 → 比赛结束 → 返回菜单 → 释放。可以抓到我们自己代码里的运行时错误，但**验证不了 three.js API 的实际效果，也验证不了画面**。three 用到的类/常量已人工核对 r169 中都存在。

第一次在浏览器打开时，建议先跑一下 `npm run typecheck`，并留意控制台是否有 WebGL / shader 警告。

## 已知简化

- 没有经济系统（购买免费）、投掷物、穿墙射击、下半场换边；友军伤害关闭。
- 地图是忠于原图走位与比例的方块化重建，不是逐面复刻；B 点后平台、窗户等用箱子近似。
- Bot 不会跳跃和蹲下；当你作为 T 带包不去下包时，T bot 会一直在包点架枪等待。
